## Быстрый запуск демонстрационного сайта (Docker Desktop)

1. Установите Docker Desktop и откройте терминал в корне репозитория.
2. Скопируйте `.env.demo.example` в `.env.demo`, замените три пароля/секрета на собственные значения (пароль тестового пользователя — минимум 8 символов).
3. Запустите:

```bash
docker compose --env-file .env.demo -f docker-compose.demo.yml up --build -d
```

4. Дождитесь запуска контейнеров (проверка: `docker compose --env-file .env.demo -f docker-compose.demo.yml ps`) и откройте **http://localhost:3000**.
5. Тестовые пользователи: **http://localhost:3000/demo**. Вход: `+79990000001` или `+79990000002`; пароль — значение `DEMO_USER_PASSWORD` из `.env.demo`. На главной автоматически отображается вымышленный будущий матч.

Остановка: `docker compose --env-file .env.demo -f docker-compose.demo.yml down`. Данные сохраняются в отдельном томе Docker; `down -v` удалит **демонстрационную** базу. Не публикуйте демо-сервис в интернете.

> **MVP v1:** интегрированная версия с последними изменениями frontend-разработчика находится в ветке `mvp/integrated-v1`. Запуск, функции и ограничения: [docs/mvp-v1.md](docs/mvp-v1.md). Реальные платежи и перепродажа билетов пока отключены.

# PARMA RESELL

Backend для сервиса передачи права посещения отдельных домашних матчей владельцами сезонных абонементов баскетбольных клубов. Первый клуб — «ПАРМА».

> Проект находится в разработке. Реальная продажа билетов, оплата и передача прав прохода отключены до подключения официального билетного оператора и платёжной инфраструктуры.

## Технологии

Python 3.12 · Flask · SQLAlchemy · Alembic / Flask-Migrate · PostgreSQL 16 · Redis (production rate limiting) · Gunicorn · pytest.

## Локальный запуск

```bash
cp .env.example .env
docker compose up --build
```

Перед первым использованием API примените миграции:

```bash
docker compose exec web flask --app wsgi:app db upgrade
```

Если сервис в Compose называется иначе, замените `web` на имя соответствующего сервиса.

Проверка: `GET http://localhost:5000/api/health` — доступность приложения; `GET http://localhost:5000/api/ready` — подключение к БД; `GET http://localhost:5000/api/meta` — статус функций.

## Тестовые данные и вход по телефону

Регистрация и вход работают по номеру телефона и паролю (от 8 символов); email необязателен. История покупок доступна по `GET /api/my/orders` с Bearer-токеном.

Для создания демонстрационного матча, пользователя с абонементом и историей покупки выполните миграции, затем команду `flask --app wsgi:app seed-demo` с `ALLOW_DEMO_SEED=1` и `DEMO_USER_PASSWORD` (минимум 8 символов). Демонстрационный телефон: `+79990000001`. Подробнее: [docs/demo-data.md](docs/demo-data.md). Никаких реальных платежей или прав прохода эта команда не создаёт.

## Тесты

```bash
pip install -r requirements.txt
python -m pytest -q
```

Интеграционный тест PostgreSQL запускается при наличии переменной `TEST_POSTGRES_URL`; в GitHub Actions используется PostgreSQL 16.

## Структура

- `app/` — модели, авторизация и HTTP API.
- `migrations/` — версионированная схема базы данных.
- `tests/` — модульные и интеграционные тесты.
- `docs/` — архитектура, резервирование и эксплуатация.
- `scripts/bootstrap_db.py` — исключительно локальная и явно разрешённая инициализация тестовой схемы.

## Статус API

Реализованы базовая авторизация, публичный каталог, заявления о владении абонементом, черновики объявлений и часть административных операций. Бронирование, платежи, перепроверка билетов у оператора и передача прав прохода пока недоступны.

Документация по запуску: [docs/deployment-checklist.md](docs/deployment-checklist.md). Описание проектирования резервирования: [docs/reservation-design.md](docs/reservation-design.md).
